# A Pattern Language (Alexander, Ishikawa, Silverstein, 1977)

253 建筑模式，组合成一种*设计语言*。每个模式以 Context → Problem → Forces → Solution → Resulting-context 的形式呈现。质量评级：无星（候选）/ 一星（有用）/ 二星（必然）。

软件工程借用了这本书几乎所有东西：GoF 设计模式、Coplien 组织模式、Fowler 企业模式，全部是对 Alexander 形式的致敬或模仿。这个 lens 坚持原书纪律：
- 必须有 ≥2 独立实例才能算 pattern
- Forces 必须真实冲突，否则是 recipe 不是 pattern
- 质量评级不是商业价值，是 *必然性* 的度量

## 核心启发
- 模式的客观性不来自权威，来自 *被多个独立领域重复验证*
- 语言（而非个例）是知识的单位
