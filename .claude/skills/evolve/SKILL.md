# /evolve — Vault Self-Evolution

## Philosophy

A vault that only accepts inputs is a passive file system. A self-evolving vault **tells you what it should study next** based on its own topology, bias, and authority-anchor health.

`/evolve` reads `wiki/_insights.md` (generated by `tools/graph_analyzer.py`) and turns its "content gaps" section into actionable work. Under the active lens, gaps are surfaced in lens-native vocabulary (aesthetic-warburg: Pathosformel / panel / authority anchor; engineering-alexander: pattern / force / incident; general-zettelkasten: concept-cluster / atomic-note).

> **v2.1 note** — the gap-action playbooks below are currently v1.4-shaped around aesthetic-warburg semantics (Wikidata / Getty AAT / Warburg panel). Full lens-aware rerouting of the per-kind executors is tracked in ROADMAP as a Sprint 3+ target. Until then, `/evolve` under a non-aesthetic lens will surface gaps but defer execution to manual follow-up.

## Invocation

```
/evolve                       # default: list top 3 gaps with suggestions
/evolve --list-all            # list all gaps (can be dozens)
/evolve --take <N>            # accept gap N and execute it automatically
/evolve --take <N> --dry-run  # show what would happen without executing
/evolve --rebuild-insights    # re-run tools/graph_analyzer.py before consulting
/evolve --priority high       # filter by priority
/evolve --kind <kind>         # filter by gap kind (missing_authority_anchor / underpopulated_domain / understaffed_panel / orphan_aesthetic / disconnected_clusters)
```

## Execution flow

### Step 1 — Ensure insights are fresh

If `wiki/_insights.md` is missing OR its `updated:` frontmatter is >7 days old, run `python3 -m tools.graph_analyzer --vault <path>` from the repo root first. (Both `-m` and the bare-script form work; `-m` is the canonical invocation — it is immune to PYTHONPATH surprises and matches how `/lint --rebuild-graph` spawns the analyzer internally.) Otherwise use existing.

Flag `--rebuild-insights` forces regeneration.

### Step 2 — Parse gaps from `_insights.md`

Extract the `## 3. Content Gaps` section. Each gap is:

```
- **<kind>** · <suggestion>
```

Group by priority (high / medium / low). The `_index/insights.json` companion file has machine-readable gap list — prefer parsing JSON when available.

### Step 3 — Default mode: Present top 3

For `/evolve` (no flags), show:

```
Vault Self-Evolution Report · <DATE>

Top 3 priorities (filtered by priority=high, fallback to medium):

  1. [HIGH] <kind>: <target>
     问题:  <what's missing>
     建议:  <concrete action>
     执行:  /evolve --take 1   (自动执行)
         或 /evolve --take 1 --dry-run   (先预览)

  2. [HIGH] ...

  3. [MEDIUM] ...

其他 <M> 条 gap:  /evolve --list-all

下次刷新 insights:  /evolve --rebuild-insights
```

### Step 4 — Execute mode (`--take N`)

For each gap kind, the execution strategy differs:

#### `missing_authority_anchor` (schema §11 violation)

Target is a slug (aesthetic or panel) with all authority fields null.

Action plan:
1. Read the target MD — especially its `title`, `aliases`, `aat_uncertainty`, `wikidata_uncertainty`
2. Query external sources to find IDs:
   - Wikidata SPARQL: `https://query.wikidata.org/sparql` — search by label
   - Getty AAT: `https://vocab.getty.edu/aat/` — search by title / aliases
   - Iconclass: `https://iconclass.org/` — for subject-matter resolution
3. For each resolved ID, Edit the target MD's frontmatter field (via Edit tool, atomic)
4. If no confident resolution, append candidates to `<field>_uncertainty`
5. Re-run `/check --aesthetics` on the target to confirm schema compliance
6. Log the action to `wiki/log.md` + `wiki/_log/usage.jsonl`

#### `underpopulated_domain`

Target is a domain name (e.g. `photo`).

Action plan:
1. Read `wiki/_refs/_domains/<domain>.md` for canonical 5 books
2. Pick 1-2 authors/works from canonical list that are NOT yet in `wiki/aesthetic/`
3. Draft a research brief the user can feed into `/ingest <url-or-path>`; for aesthetic lenses with a concrete visual source, `/taste <image>` directly
4. Announce:

   ```
   要补强 `photo` 域，建议下一步：
     - Sontag, *On Photography* 核心章节 → /ingest <url or local PDF> "Sontag 1977"
     - Szarkowski《The Photographer's Eye》五要素 → 若有合适 public-domain 图 可直接 /taste
   接受此建议? (y/n/other)
   ```

Unless `--auto-execute` flag passed, wait for confirmation before executing.

#### `understaffed_panel`

Target is a panel slug with <3 members.

Action plan:
1. Read panel MD — its `## Pathosformel statement` + existing members
2. Query LLM (via Claude Code's built-in, no MCP needed for brainstorm): "给定 Pathosformel 「X」和当前成员 [[A]], [[B]], 建议跨时代/跨媒介补充 3 个候选节点"
3. Present candidates. Each candidate is either:
   - (a) Already in vault → add wikilink to panel's `members:` via Edit
   - (b) Not yet in vault → surface as `/taste` (aesthetic lens) or `/ingest` target
4. Optionally mark panel `incomplete: true` in frontmatter when Pathosformel genuinely has few historical instances

#### `orphan_aesthetic`

Target is an aesthetic with degree ≤1.

Action plan:
1. Read the card's core observation + prompts
2. Run the vault cross-link pass (direct Grep for aliases + wikidata sibling search across `wiki/{tier_0,tier_1_*}/`) to discover latent wikilink candidates
3. If no existing panel fits, propose a new panel via `/panel --suggest <slug>`
4. Last resort: mark `no_known_lineage: true` in frontmatter (explicit stance, not neglect)

#### `disconnected_clusters`

Target is a cluster pair.

Action plan:
1. Read representative nodes from each cluster
2. Propose a bridging Pathosformel ("what single visual formula unites these?")
3. If user accepts, either:
   - Create new panel MD listing both as members
   - Add `inspired_by` or `frames` relation between one representative from each cluster

### Step 5 — Log and update

After any execution:

1. Append to `wiki/log.md`:
   ```
   - YYYY-MM-DD /evolve --take N → <kind>: <what was done>
   ```
2. Append to `wiki/_log/usage.jsonl`:
   ```json
   {"action": "evolve", "kind": "<kind>", "target": "<slug>", "outcome": "<summary>", "timestamp": "..."}
   ```
3. Invalidate `_insights.md` — since graph changed, mark it as stale so next `/evolve` call regenerates

### Step 6 — Stop conditions

- **All high-priority gaps resolved** → report success, suggest `/evolve --priority medium` for next wave
- **User declines** → mark gap as `dismissed` by appending to `wiki/_insights.md` § "Dismissed gaps" with timestamp
- **Execution fails** (e.g. external API down) → log failure, revert any partial writes, report to user

## Output format

Always produce a concise report:

```
/evolve complete.

Executed:
  <kind>: <target> → <action taken>

Changes:
  <file 1> (Edit: <field>)
  <file 2> (new)

Next steps:
  /evolve                     # next gap
  /check                      # verify compliance
  /evolve --rebuild-insights  # if you edited many files manually
```

## Safety rails

- Never edit schema.md, CLAUDE.md, PRD-zh.md, PRD.md, LICENSE, or any `_refs/_spine/` / `_refs/_institutions/` canonical entries through `/evolve`. These require explicit user decision.
- Never execute `/taste` without Phoenix's confirmation when it requires a paste-image step (can't auto-paste).
- Never fabricate Getty AAT IDs, Iconclass notations, or museum accession numbers. If Wikidata/Getty/Iconclass query returns uncertain, write `null` + `*_uncertainty` candidates.
- Respect 14-day grace for authority anchors (v1.4 §11 rule) — if a card was created <14 days ago, still surface but don't block.

## Schema reference

- `schema.md §11` — authority anchor hard rule
- `schema.md §6` — Warburg panel structure
- `wiki/_insights.md` — gap source
- `wiki/_index/insights.json` — machine-readable gap list
- `tools/graph_analyzer.py` — insights generator

## Relation to other skills

- `/check` surfaces schema violations (compliance oracle)
- `/evolve` turns them into actions (executor)
- `/taste` produces new aesthetic cards (creation)
- `/ingest` (lens-aware): fetches + routes URL / PDF / image / markdown / text into tier-0 under the active lens's entity model
- `/prompt --test` validates prompts (real generation regression)

`/evolve` orchestrates these skills to close gaps. It does not replace them.
