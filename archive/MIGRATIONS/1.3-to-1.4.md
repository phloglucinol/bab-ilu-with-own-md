# Schema Migration · v1.3.0 → v1.4.0

*Date: 2026-04-16*
*Type: Additive minor bump. Non-breaking.*

## Summary

v1.4 delivers three-axis alignment:

- **Axis 1 (Karpathy UX)**: adds `wiki/index.md` + `wiki/log.md` (human-readable canonical primitives)
- **Axis 2 (OmegaWiki academic)**: physically installs 18 inherited skills + MCP llm-review + Python tools + 33 tests + arXiv daily cron
- **Axis 3 (multi-practitioner aesthetic)**: adds `ux` + `painting` domains, `iconclass` field, museum/institution ID fields, `ux_flow` + `painting` + `motion` opt-in prompt modalities, authoritative-citation hard rule, `wiki/_refs/` reference library

### Added — `type: source` field (for `_refs/` entries)

```yaml

```

Marks an entry as authoritative reference. `canonical: true` requires explicit human commit; LLM writes default `false`.

### Unchanged

- Entity types (still 11: source / concept / topic / person / idea / experiment / claim / summary / question / aesthetic / prompt)
- Relation types (still 12: extends / contradicts / supports / inspired_by / tested_by / invalidates / supersedes / addresses_gap / derived_from / applies / exemplifies / frames)
- Section-marker conventions (`<!-- llm:section-start -->` etc.)
- Panofsky layer enum, Warburg panel structure, Getty AAT / Wikidata fields

## New hard rule (§11)

> Every `type: aesthetic` and `type: panel` MUST have at least one authoritative anchor field non-null: `aat_id` / `wikidata` / `iconclass` / `ulan_id` / any museum/institution ID / `iso_standard` / `nng_url`. LLM may leave all null ONLY during the 14-day grace window with each unresolved candidate recorded in the matching `*_uncertainty` field. Enforced by `/check` Category 10.

## Migration procedure

For existing 1.3.0 entries:

```
/check --migrate --dry-run      # show per-file additive diff
/check --migrate                 # apply: add null fields, bump schema_version to 1.4.0
```

Never rewrites body content. Never changes existing field values. Pure additive.

For the 4 person-typed files in `wiki/aesthetics/{cinema,photo,graphic,architecture}/`:
- Move to `wiki/people/{domain}/`
- Create 30-day symlink at old path for reference stability
- `/check --migrate` handles this automatically when migrating to 1.4

## Rollback

Unlikely needed — v1.4 is purely additive. If rollback required:
- Drop the new fields from frontmatter (they are all optional)
- Drop the new directories (`_refs/`, `people/` — they don't block anything)
- Roll `schema_version:` back to 1.3.0 in frontmatter
- Note: rollback does NOT uninstall the OmegaWiki skills or tools — those remain usable even at schema v1.3.0
